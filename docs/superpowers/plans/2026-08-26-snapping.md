# Snapping Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Attract the cursor to lines and points the editor derives from the drawing, so an edited point sits on a line and slides along it.

**Architecture:** One pure core module holds candidate construction, the pull model and
resolution. One editor module holds gesture state, exclusions and the two entry points.
One visualization layer draws every held candidate back to the geometry it came from.
The resolver is a function of the cursor. It returns a position and never writes.

**Tech Stack:** JavaScript ES modules. Mocha and chai in `fontra-core`. No new dependency.

**Spec:** `docs/superpowers/specs/snapping.md`

## Global Constraints

- **R-A** — pure geometry in `fontra-core/src/`, hit-testing in `scene-model.js`, interaction in
  a dedicated `*-interactions.js`, drawing in a `visualization-layer-*.js`.
  `edit-tools-pointer.js` stays a thin dispatcher.
- **R-B** — one copy of every constant and geometry function. Import, never re-derive.
- **R-C** — every skeleton mutation goes through `editSkeleton`. The resolver returns a
  position. It never writes.
- **R-D** — provenance forward, never recovered. Exclusions read the provenance map. Nothing
  matches generated points to skeleton points by geometry.
- **R-E** — no kind-branching in shared emit code.
- **R-G** — `fontra-core` carries mocha tests. `views-editor` has no harness, so every editor
  task carries a manual test matrix.
- Every commit runs `node --check` on each touched editor file, then `npx prettier --write`.
  The user runs bundle-watch and reports compilation errors.
- Distance is measured in pixels. Nothing derived from pixels reaches stored geometry.
- No state survives a gesture. The file records coordinates only.
- Stage with `git add .`.

## Decisions this plan makes, and what they rest on

The spec left four items open in its §12. Three are settled here from
`_external/_snapping/inkscape`. The fourth is deferred by the spec itself.

**Candidate density (§12.2) — cull, do not reduce the rule.** Two culls, both from
Inkscape.

1. **Distance.** Inkscape expands the bounding box of the moved geometry by the snap
   tolerance and keeps only objects that intersect it, and only objects inside the visible
   area (`snap.cpp`, `SnapManager::_findCandidates`). It also caps the candidate list at 200
   and warns. We take the same shape: a source contributes only inside a collection radius
   around the cursor, and the survivor list is capped.
2. **Side.** Inkscape's alignment snapper keeps, among all sources whose ray is within
   tolerance, the one whose source point is nearest the cursor along that ray
   (`alignment-snapper.cpp`, `_snapBBoxPoints`, the `getDistanceToAlignTarget` test). A
   horizontal ray through a point 300 units left of the cursor is the same line as one
   through a point 3 units left, so the far one adds nothing and draws a longer, less
   readable guide. We take that rule and split it by direction: the nearest source on each
   side of the cursor survives, so a guide stays available on both flanks. Four rays from N
   points instead of 2N.

**The crossing (§2).** Inkscape intersects only lines already within tolerance
(`snapped-line.cpp`, `getClosestIntersectionSL` over the in-range list). Confirmed: compute
the crossing at resolution time, store nothing. Inkscape does **not** refuse a shallow
crossing, only a parallel one. Our refusal is an addition, and it rests on this fork's own
precedent — the miter limit of 4 in `offset-contour.js` and
`MIN_AXIS_TANGENT_SEPARATION_DEG` in the serif.

**The comparison is one scalar.** Inkscape's `isOtherSnapBetter`
(`snapped-point.cpp`) is eleven booleans with four veto clauses, and it is not a total
order. The spec's `weight × falloff(distance)` is, and every rank in its §4 table is
expressible as a weight. Keep it one number.

**The suppress key (§12.4) is now a switch (Shift+G), per the designer.** Shift+G is today
`action.toggle-magnetic-snap` (`scene-controller.js:705-712`), which §7 of the spec removes.
The same task frees the key and re-takes it.

**Every dragged point is asked, not one anchor.** Inkscape resolves each dragged point
separately, and each one produces its own candidate transform. It then compares those results
against each other and keeps one (`pure-transform.cpp:68-99`). The spec did not state this,
and an anchor-only rule is worse: drag a shape by one corner toward an alignment its opposite
corner would make, and the magnet never registers the alignment the designer is aiming at.
Every dragged on-curve is asked, and the strongest pull across the set wins.

**Across points, distance alone is the wrong comparison.** Several points can be near
something at once, and ranking on snap distance alone hands the shape to whichever point lies
nearest a guide, which may be the point furthest from the hand. The shape then jumps to an
alignment the designer was not watching. Inkscape blends the snap distance with each point's
distance to the pointer, at a ratio the user can set. We take the blend and fix the ratio,
because a preference for it is a question nobody can answer.

**Handles are not asked.** Only the dragged on-curves. A handle states a direction, so
aligning it to a metric line means nothing. This is the same reason handles generate no rays
in Task 4.

**A shift-constrained drag makes the constraint a held line.** Inkscape carries a second
entry point for the constrained case, and ships two behaviors behind a preference: snap along
the constraint, or free-snap and then project onto it. We need neither, because the resolver
already has the concept. The constraint enters as a held line of unbounded weight, so the
gesture starts at one degree of freedom, and the resolver's existing search for a second line
finds where a candidate crosses the constraint. Shift then cannot be overruled by a magnet,
which is what shift is for, and snapping decides only where along the axis the point sits.

**A point on a curve is refused, and this is a decision rather than an omission.** Inkscape
snaps to paths themselves, to path crossings, and to tangential and perpendicular positions
on them. We offer node rays and endpoint tangent extensions only. A point landing on another
contour's curve is rarely what a type designer means, and every such target is a moving one:
it has no name a guide can be drawn back to, which the drawing rule in §8 requires.

**The numbers are provisional.** Every constant in Task 3 is a starting value, tuned later
against a real glyph. They live in one exported block so a tuning session edits one place.

**One cost of the single scalar, stated.** Inkscape normalizes each candidate's distance by
its own family's tolerance, so a metric can carry a larger grab radius than a smart guide
independently of which wins a tie. Ours has one reach and lets weight do both jobs, so those
two properties cannot move apart. If tuning wants them separate, the honest fix is a per-kind
reach, not a heavier weight.

  - `projectOntoLine(candidate, point)` → `{ x, y }`, the foot of the perpendicular.
  - `distanceToCandidate(candidate, point)` → number, in the same units as the inputs.

```js
export const KIND = Object.freeze({
  METRIC: "metric",
  GUIDE_INTERSECTION: "guideIntersection",
  GUIDE_ORTHOGONAL: "guideOrthogonal",
  GUIDE_SLANTED: "guideSlanted",
  SMART_INTERSECTION_ORTHOGONAL: "smartIntersectionOrthogonal",
  SMART_INTERSECTION_SLANTED: "smartIntersectionSlanted",
  SMART_ORTHOGONAL: "smartOrthogonal",
  SMART_SLANTED: "smartSlanted",
  OTHER: "other",
});

export function makeLineCandidate({ x, y, angle, kind, source }) {
  const radians = (angle * Math.PI) / 180;
  return {
    type: "line",
    x,
    y,
    dx: Math.cos(radians),
    dy: Math.sin(radians),
    kind,
    source: source || { x, y },
  };
}

export function makePointCandidate({ x, y, kind, source }) {
  return { type: "point", x, y, kind, source: source || { x, y } };
}

export function projectOntoLine(candidate, point) {
  const vx = point.x - candidate.x;
  const vy = point.y - candidate.y;
  const along = vx * candidate.dx + vy * candidate.dy;
  return {
    x: candidate.x + along * candidate.dx,
    y: candidate.y + along * candidate.dy,
  };
}

export function distanceToCandidate(candidate, point) {
  if (candidate.type === "point") {
    return Math.hypot(point.x - candidate.x, point.y - candidate.y);
  }
  const foot = projectOntoLine(candidate, point);
  return Math.hypot(point.x - foot.x, point.y - foot.y);
}
```

```js
export const MIN_CROSSING_ANGLE_DEG = 15;

const GUIDE_KINDS = new Set([KIND.METRIC, KIND.GUIDE_ORTHOGONAL, KIND.GUIDE_SLANTED]);
const ORTHOGONAL_KINDS = new Set([
  KIND.METRIC,
  KIND.GUIDE_ORTHOGONAL,
  KIND.SMART_ORTHOGONAL,
]);

export function crossLines(a, b) {
  const cross = a.dx * b.dy - a.dy * b.dx;
  const sinLimit = Math.sin((MIN_CROSSING_ANGLE_DEG * Math.PI) / 180);
  if (Math.abs(cross) < sinLimit) {
    return null;
  }
  const t = ((b.x - a.x) * b.dy - (b.y - a.y) * b.dx) / cross;
  const x = a.x + t * a.dx;
  const y = a.y + t * a.dy;
  let kind;
  if (GUIDE_KINDS.has(a.kind) && GUIDE_KINDS.has(b.kind)) {
    kind = KIND.GUIDE_INTERSECTION;
  } else if (ORTHOGONAL_KINDS.has(a.kind) && ORTHOGONAL_KINDS.has(b.kind)) {
    kind = KIND.SMART_INTERSECTION_ORTHOGONAL;
  } else {
    kind = KIND.SMART_INTERSECTION_SLANTED;
  }
  return { ...makePointCandidate({ x, y, kind, source: a.source }), sources: [a, b] };
}
```

## Task 3: The pull model and the resolver

**Files:**

- Modify: `src-js/fontra-core/src/snapping.js`
- Test: `src-js/fontra-core/tests/test-snapping.js`

**Interfaces:**

- Consumes: Task 1 and Task 2.
- Produces:
  - `SNAP_PARAMETERS` — a frozen block of the provisional numbers:
    `{ reachPixels: 12, weights: { ... }, holdBonus: 1.3, noSnapPull: 0.15, pointerWeight: 0.5 }`.
    `weights` carries one entry per `KIND` value.
  - `candidatePull(candidate, cursor, { pixelUnit, held })` → number. `pixelUnit` is the glyph
    units per screen pixel. `held` is the previously held candidate or `null`.
  - `resolveSnap(candidates, cursor, { pixelUnit, held, constraint })` →
    `{ position: {x, y}, pull, held: [candidate, ...], freedom: "free" | "line" | "point" }`.
    `held` holds at most two entries. `freedom` says what the grid may still round. `pull` is
    the winning candidate's pull, or 0 where nothing won. `constraint` is optional: a line
    candidate the result must stay on. Where it is given the gesture starts at one degree of
    freedom, so the resolver's existing second-line search returns where a candidate crosses
    the constraint. That is the whole of the shift-constrained case.
  - `resolveSnapForPoints(candidates, points, cursor, { pixelUnit, held })` →
    `{ delta: {x, y}, pointIndex, position, pull, held, freedom }`, or a zero delta with an
    empty `held` where nothing won. `points` is the dragged on-curves at their would-be
    positions. `pointIndex` names which of them won, so the caller can carry the hold.

**The rule, stated.** Every candidate produces `weight × falloff(distance / reach)`, with
`falloff(u) = max(0, 1 - u²)`. A held candidate's weight is multiplied by `holdBonus`. A
constant `noSnapPull` is the floor every candidate must beat. So the release rule the spec
asks for is not written separately: a held candidate's pull falls as the cursor moves away,
and the constant overtakes it.

**Across points, the pull is discounted by how far that point is from the cursor.** Each
dragged point resolves on its own, and its winning pull is then multiplied by
`1 - pointerWeight × min(1, pointerDistance / (reach × 8))`. So the point under the hand is
preferred, and a much stronger alignment elsewhere in the selection can still take the drag.
At `pointerWeight: 0` the rule is the plain strongest pull. At 1 only the point under the
cursor can ever win.

**The hold belongs to the pair, the point and its candidate together.** Where two points are
both near guides, remembering only the candidate lets the winner alternate between the two
points from frame to frame, and the selection flickers between two alignments. The hold bonus
applies only where the same point holds the same candidate.

```js
describe("the pull model", () => {
```

```js
export const SNAP_PARAMETERS = Object.freeze({
  reachPixels: 12,
  holdBonus: 1.3,
  noSnapPull: 0.15,
  pointerWeight: 0.5,
  pointerFalloffReaches: 8,
  weights: Object.freeze({
    [KIND.METRIC]: 1.0,
    [KIND.GUIDE_INTERSECTION]: 0.84,
    [KIND.GUIDE_ORTHOGONAL]: 0.8,
    [KIND.GUIDE_SLANTED]: 0.76,
    [KIND.SMART_INTERSECTION_ORTHOGONAL]: 0.52,
    [KIND.SMART_INTERSECTION_SLANTED]: 0.48,
    [KIND.SMART_ORTHOGONAL]: 0.44,
    [KIND.SMART_SLANTED]: 0.4,
    [KIND.OTHER]: 0.3,
  }),
});

function falloff(u) {
  return u >= 1 ? 0 : 1 - u * u;
}

function sameCandidate(a, b) {
  if (!a || !b || a.type !== b.type || a.kind !== b.kind) {
    return false;
  }
  if (a.type === "point") {
    return Math.abs(a.x - b.x) < 1e-9 && Math.abs(a.y - b.y) < 1e-9;
  }
  const parallel = Math.abs(a.dx * b.dy - a.dy * b.dx) < 1e-9;
  return parallel && Math.abs((b.x - a.x) * a.dy - (b.y - a.y) * a.dx) < 1e-9;
}

export function candidatePull(candidate, cursor, { pixelUnit, held }) {
  const reach = SNAP_PARAMETERS.reachPixels * pixelUnit;
  const weight =
    SNAP_PARAMETERS.weights[candidate.kind] ?? SNAP_PARAMETERS.weights[KIND.OTHER];
  const bonus = sameCandidate(candidate, held) ? SNAP_PARAMETERS.holdBonus : 1;
  return weight * bonus * falloff(distanceToCandidate(candidate, cursor) / reach);
}

export function resolveSnap(candidates, cursor, options) {
  const { constraint } = options;
  if (constraint) {
    // The constraint is a held line, so the gesture already stands at one degree of
    // freedom and the search below looks for the second. Shift is not overruled.
    const onConstraint = projectOntoLine(constraint, cursor);
    for (const candidate of candidates) {
      if (candidate.type !== "line") {
        continue;
      }
      if (candidatePull(candidate, cursor, options) <= SNAP_PARAMETERS.noSnapPull) {
        continue;
      }
      const crossing = crossLines(constraint, candidate);
      if (!crossing) {
        continue;
      }
      const pull = candidatePull(crossing, cursor, options);
      if (pull > SNAP_PARAMETERS.noSnapPull) {
        return {
          position: { x: crossing.x, y: crossing.y },
          pull,
          held: [candidate],
          freedom: "point",
        };
      }
    }
    return { position: onConstraint, pull: 0, held: [], freedom: "line" };
  }

  const scored = [];
  for (const candidate of candidates) {
    const pull = candidatePull(candidate, cursor, options);
    if (pull <= SNAP_PARAMETERS.noSnapPull) {
      continue;
    }
    if (scored.some(({ candidate: other }) => sameCandidate(other, candidate))) {
      continue;
    }
    scored.push({ candidate, pull });
  }
  scored.sort((a, b) => b.pull - a.pull);

  if (!scored.length) {
    return { position: { ...cursor }, pull: 0, held: [], freedom: "free" };
  }

  const winner = scored[0].candidate;
  if (winner.type === "point") {
    return {
      position: { x: winner.x, y: winner.y },
      pull: scored[0].pull,
      held: winner.sources ? [...winner.sources] : [winner],
      freedom: "point",
    };
  }

  for (const { candidate } of scored.slice(1)) {
    if (candidate.type !== "line") {
      continue;
    }
    const crossing = crossLines(winner, candidate);
    if (!crossing) {
      continue;
    }
    const crossingPull = candidatePull(crossing, cursor, options);
    if (crossingPull > SNAP_PARAMETERS.noSnapPull) {
      return {
        position: { x: crossing.x, y: crossing.y },
        pull: crossingPull,
        held: [winner, candidate],
        freedom: "point",
      };
    }
  }

  return {
    position: projectOntoLine(winner, cursor),
    pull: scored[0].pull,
    held: [winner],
    freedom: "line",
  };
}

export function resolveSnapForPoints(candidates, points, cursor, options) {
  const reach = SNAP_PARAMETERS.reachPixels * options.pixelUnit;
  const pointerSpan = reach * SNAP_PARAMETERS.pointerFalloffReaches;
  const noWin = {
    delta: { x: 0, y: 0 },
    pointIndex: -1,
    position: null,
    pull: 0,
    held: [],
    freedom: "free",
  };
  let best = noWin;
  let bestScore = 0;

  points.forEach((point, pointIndex) => {
    // The hold belongs to the pair. A candidate held by another point earns no bonus here.
    const held =
      options.held && options.held.pointIndex === pointIndex
        ? options.held.candidate
        : null;
    const result = resolveSnap(candidates, point, { ...options, held });
    if (!result.held.length) {
      return;
    }
    const pointerDistance = Math.hypot(point.x - cursor.x, point.y - cursor.y);
    const discount =
      1 - SNAP_PARAMETERS.pointerWeight * Math.min(1, pointerDistance / pointerSpan);
    const score = result.pull * discount;
    if (score > bestScore) {
      bestScore = score;
      best = {
        delta: { x: result.position.x - point.x, y: result.position.y - point.y },
        pointIndex,
        position: result.position,
        pull: result.pull,
        held: result.held,
        freedom: result.freedom,
      };
    }
  });

  return best;
}
```

**The two culls.**

- **Distance** — a source outside `collectionRadiusPixels × pixelUnit` of the cursor
  contributes nothing. After generation the list is capped at `maxCandidates`, strongest
  weight first, then nearest first, so the cap is stable rather than arbitrary.
- **Side** — for the horizontal rays and again for the vertical rays, keep the
  `perSideCount` nearest sources on each side of the cursor. A source exactly on the cursor's
  axis counts as the positive side. Metrics and permanent guides are never culled by side:
  the designer placed them and there are few.

```js
export const CULL_PARAMETERS = Object.freeze({
  collectionRadiusPixels: 400,
  perSideCount: 1,
  maxCandidates: 200,
});

function isOrthogonal(angle) {
  const a = ((angle % 180) + 180) % 180;
  return Math.abs(a) < 1e-9 || Math.abs(a - 90) < 1e-9;
}

function nearestPerSide(sources, cursor, axis) {
  // axis "y": horizontal rays, compared by the source's y. axis "x": vertical rays.
  const above = [];
  const below = [];
  for (const source of sources) {
    (source[axis] >= cursor[axis] ? above : below).push(source);
  }
  const byDistance = (a, b) =>
    Math.abs(a[axis] - cursor[axis]) - Math.abs(b[axis] - cursor[axis]);
  above.sort(byDistance);
  below.sort(byDistance);
  return [
    ...above.slice(0, CULL_PARAMETERS.perSideCount),
    ...below.slice(0, CULL_PARAMETERS.perSideCount),
  ];
}

export function collectCandidates(scene, cursor, { pixelUnit }) {
  const radius = CULL_PARAMETERS.collectionRadiusPixels * pixelUnit;
  const inRadius = (p) => Math.hypot(p.x - cursor.x, p.y - cursor.y) <= radius;
  const candidates = [];

  for (const metric of scene.metrics || []) {
    candidates.push(
      makeLineCandidate({
        x: cursor.x,
        y: metric.value,
        angle: 0,
        kind: metric.kind === "band" ? KIND.OTHER : KIND.METRIC,
        source: { x: cursor.x, y: metric.value },
      })
    );
  }

  for (const guide of scene.guides || []) {
    candidates.push(
      makeLineCandidate({
        x: guide.x,
        y: guide.y,
        angle: guide.angle,
        kind: isOrthogonal(guide.angle) ? KIND.GUIDE_ORTHOGONAL : KIND.GUIDE_SLANTED,
        source: { x: guide.x, y: guide.y },
      })
    );
  }

  const points = (scene.points || []).filter(inRadius);
  for (const source of nearestPerSide(points, cursor, "y")) {
    candidates.push(
      makeLineCandidate({
        x: source.x,
        y: source.y,
        angle: 0,
        kind: KIND.SMART_ORTHOGONAL,
        source,
      })
    );
  }
  for (const source of nearestPerSide(points, cursor, "x")) {
    candidates.push(
      makeLineCandidate({
        x: source.x,
        y: source.y,
        angle: 90,
        kind: KIND.SMART_ORTHOGONAL,
        source,
      })
    );
  }

  for (const segment of (scene.segments || []).filter(inRadius)) {
    candidates.push(
      makeLineCandidate({
        x: segment.x,
        y: segment.y,
        angle: segment.angle,
        kind: isOrthogonal(segment.angle) ? KIND.SMART_ORTHOGONAL : KIND.SMART_SLANTED,
        source: { x: segment.x, y: segment.y },
      })
    );
  }

  candidates.sort((a, b) => {
    const weightDelta =
      (SNAP_PARAMETERS.weights[b.kind] ?? 0) - (SNAP_PARAMETERS.weights[a.kind] ?? 0);
    if (Math.abs(weightDelta) > 1e-12) {
      return weightDelta;
    }
    return distanceToCandidate(a, cursor) - distanceToCandidate(b, cursor);
  });
  return candidates.slice(0, CULL_PARAMETERS.maxCandidates);
}
```

```js
export function roundSnapped(result, roundFunc) {
  const { position, held, freedom } = result;
  if (freedom === "point") {
    return { ...position };
  }
  if (freedom === "free" || !held.length) {
    return { x: roundFunc(position.x), y: roundFunc(position.y) };
  }
  const line = held[0];
  const along = (position.x - line.x) * line.dx + (position.y - line.y) * line.dy;
  const rounded = roundFunc(along);
  return { x: line.x + rounded * line.dx, y: line.y + rounded * line.dy };
}
```

## Task 7: The snapping session, with exclusions

**Files:**

- Create: `src-js/views-editor/src/snapping-interactions.js`
- Modify: `src-js/views-editor/src/scene-model.js` — add the held-candidate field

**Interfaces:**

- Consumes: `collectCandidates`, `resolveSnap`, `resolveSnapForPoints`, `roundSnapped` from
  `snapping.js`.
- Produces:
  - `class SnappingSession` with:
    - `constructor(sceneController, { excludePointIndices })`
    - `resolve(point, { constraint } = {})` → `{ x, y }`, the snapped and rounded position of
      one point. The pen uses this. Publishes the held candidates on
      `sceneController.sceneModel.snapHeldCandidates`.
    - `resolveSet(points, cursor, { constraint } = {})` → `{ x, y }`, the correction to add to
      the drag's raw delta. The pointer uses this. It resolves every point, keeps the winner,
      carries the winning `pointIndex` in the hold, and publishes the same draw state.
      Returns a zero correction where nothing won.
    - `end()` — clears the held candidates and the published draw state.
  - `buildSnapScene(sceneController, excludePointIndices)` → the plain `scene` object
    Task 4 consumes.

**Exclusions, per spec §6.**

1. The geometry being moved contributes nothing. The caller passes its point indices.
2. In the pen, the point being placed contributes nothing. The previous point of the chain
   does, and it is the most useful source there.
3. Generated geometry derived from the moved geometry contributes nothing. Dragging a
   skeleton point moves the generated points that carry its provenance on every frame, so a
   guide off one of those would chase the drag. The provenance map answers which points those
   are. This is a lookup, per R-D. Nothing matches by geometry.

Generated geometry is a candidate source and never a snap subject. The session resolves a
position. It never writes, so it cannot place a generated point (R-C).

- [ ] **Step 1: Write the module**

```js
import {
  collectCandidates,
  resolveSnap,
  resolveSnapForPoints,
  roundSnapped,
} from "@fontra/core/snapping.js";
import { getSkeletonData } from "@fontra/core/skeleton-model.js";

export function buildSnapScene(sceneController, excludePointIndices) {
  const positionedGlyph = sceneController.sceneModel.getSelectedPositionedGlyph();
  const glyph = positionedGlyph?.glyph;
  if (!glyph) {
    return { metrics: [], guides: [], points: [], segments: [] };
  }
  const excluded = excludedPointIndices(sceneController, excludePointIndices);

  const metrics = [];
  const lineMetrics =
    sceneController.sceneModel.fontSourceInstance?.lineMetricsHorizontalLayout || {};
  for (const [name, metric] of Object.entries(lineMetrics)) {
    metrics.push({ name, value: metric.value, kind: "metric" });
    if (metric.zone) {
      metrics.push({
        name: `${name}Zone`,
        value: metric.value + metric.zone,
        kind: "band",
      });
    }
  }

  const guides = [
    ...(glyph.guidelines || []),
    ...(sceneController.sceneModel.fontSourceInstance?.guidelines || []),
  ].map((guideline) => ({ x: guideline.x, y: guideline.y, angle: guideline.angle }));

  const points = [];
  const segments = [];
  const path = glyph.path;
  for (let i = 0; i < path.numPoints; i++) {
    if (excluded.has(i)) {
      continue;
    }
    const point = path.getPoint(i);
    if (point.type) {
      continue; // off-curve points contribute no rays
    }
    points.push({ x: point.x, y: point.y });
  }
  for (const segment of iterPathSegments(path)) {
    if (segment.pointIndices.some((i) => excluded.has(i))) {
      continue;
    }
    segments.push(segment.candidate);
  }
  return { metrics, guides, points, segments };
}

function excludedPointIndices(sceneController, movedPointIndices) {
  const excluded = new Set(movedPointIndices);
  const positionedGlyph = sceneController.sceneModel.getSelectedPositionedGlyph();
  const skeletonData = getSkeletonData(positionedGlyph?.glyph);
  if (!skeletonData) {
    return excluded;
  }
  // R-D: the generated points that follow the moved skeleton points are a provenance
  // lookup, never a geometric match.
  for (const [pointIndex, provenance] of iterGeneratedProvenance(skeletonData)) {
    if (movedSkeletonPointIds(sceneController).has(provenance.skeletonPointId)) {
      excluded.add(pointIndex);
    }
  }
  return excluded;
}

export class SnappingSession {
  constructor(sceneController, { excludePointIndices = [] } = {}) {
    this.sceneController = sceneController;
    this.scene = buildSnapScene(sceneController, excludePointIndices);
    this.held = null;
  }

  get enabled() {
    return !!this.sceneController.sceneSettings.snappingEnabled;
  }

  resolve(point, { constraint } = {}) {
    if (!this.enabled) {
      return point;
    }
    const pixelUnit = this.sceneController.onePixelUnit;
    const candidates = collectCandidates(this.scene, point, { pixelUnit });
    const result = resolveSnap(candidates, point, {
      pixelUnit,
      held: this.held?.candidate || null,
      constraint,
    });
    this.held = result.held.length
      ? { pointIndex: 0, candidate: result.held[0] }
      : null;
    this.sceneController.sceneModel.snapHeldCandidates = result.held;
    return roundSnapped(result, (value) => Math.round(value));
  }

  resolveSet(points, cursor, { constraint } = {}) {
    if (!this.enabled || !points.length) {
      return { x: 0, y: 0 };
    }
    const pixelUnit = this.sceneController.onePixelUnit;
    // The candidate set is built against the cursor once per frame, and every point is
    // then resolved against that one set.
    const candidates = collectCandidates(this.scene, cursor, { pixelUnit });
    const best = resolveSnapForPoints(candidates, points, cursor, {
      pixelUnit,
      held: this.held,
      constraint,
    });
    this.sceneController.sceneModel.snapHeldCandidates = best.held;
    if (best.pointIndex < 0) {
      this.held = null;
      return { x: 0, y: 0 };
    }
    // The hold is the pair. A candidate held by one point earns no bonus on another.
    this.held = { pointIndex: best.pointIndex, candidate: best.held[0] };
    const winner = points[best.pointIndex];
    const rounded = roundSnapped(
      { position: best.position, held: best.held, freedom: best.freedom },
      (value) => Math.round(value)
    );
    return { x: rounded.x - winner.x, y: rounded.y - winner.y };
  }

  end() {
    this.held = null;
    this.sceneController.sceneModel.snapHeldCandidates = [];
  }
}
```

`iterPathSegments`, `iterGeneratedProvenance` and `movedSkeletonPointIds` are the three
helpers this module needs. Do not write new copies (R-B): `iterPathSegments` wraps the path
iterator `scene-model.js` already uses for its segment hit-tests, and the other two read the
skeleton provenance map through `skeleton-model.js`. Import them, and if a needed helper is
private in `scene-model.js`, export it rather than duplicating it.

In the `SceneModel` constructor, beside the other draw-state fields:

## Task 8: The pointer drag snaps

- Modify: `src-js/views-editor/src/edit-tools-pointer.js:751-985` (`handleDragSelection`)

The drag applies a **delta** through `makeChangeForDelta`. Snapping needs positions. So the
session resolves every dragged on-curve at its would-be position, takes the strongest pull
across the set, and the drag corrects the delta once, before the change is made. That is the
same insertion point as the existing `constrainDelta` hook, and it keeps
`edit-tools-pointer.js` a dispatcher (R-A).

**One delta, whichever point wins.** The winner's correction moves the whole selection, so
the relative geometry of the dragged points is untouched. This is what lets a shape dragged
by one corner align on the opposite corner.

- [ ] **Step 1: Write the layer**

```js
import { KIND } from "@fontra/core/snapping.js";
import {
  registerVisualizationLayerDefinition,
  glyphSelector,
  strokeLine,
} from "./visualization-layer-definitions.js";

const PERMANENT_KINDS = new Set([
  KIND.METRIC,
  KIND.GUIDE_ORTHOGONAL,
  KIND.GUIDE_SLANTED,
  KIND.GUIDE_INTERSECTION,
]);

registerVisualizationLayerDefinition({
  identifier: "fontra.snapping.guides",
  name: "sidebar.user-settings.snapping-guides",
  selectionFunc: glyphSelector("editing"),
  userSwitchable: true,
  defaultOn: true,
  zIndex: 600,
  screenParameters: { strokeWidth: 1, dash: 4, markerRadius: 3 },
  colors: { permanentColor: "#00BFFF", smartColor: "#FF5FA2" },
  colorsDarkMode: { permanentColor: "#00BFFFC0", smartColor: "#FF8FC0" },
  draw: (context, positionedGlyph, parameters, model, controller) => {
    const held = model.snapHeldCandidates || [];
    if (!held.length) {
      return;
    }
    const { xMin, yMin, xMax, yMax } = controller.getViewBox();
    const reach = Math.max(Math.hypot(xMax - xMin, yMax - yMin), 2000);
    context.lineWidth = parameters.strokeWidth;
    context.setLineDash([parameters.dash, parameters.dash]);
    for (const candidate of held) {
      context.strokeStyle = PERMANENT_KINDS.has(candidate.kind)
        ? parameters.permanentColor
        : parameters.smartColor;
      // The line is drawn through the source, so the reason for the snap is visible.
      strokeLine(
        context,
        candidate.source.x - candidate.dx * reach,
        candidate.source.y - candidate.dy * reach,
        candidate.source.x + candidate.dx * reach,
        candidate.source.y + candidate.dy * reach
      );
      context.beginPath();
      context.arc(
        candidate.source.x,
        candidate.source.y,
        parameters.markerRadius,
        0,
        2 * Math.PI
      );
      context.stroke();
    }
    context.setLineDash([]);
  },
});
```

## Task 12: Tune the numbers on a real glyph

- [ ] **Step 1: Record what each number does before changing any of it**

| Number                   | What it changes                                                                                         |
| ------------------------ | ------------------------------------------------------------------------------------------------------- |
| `reachPixels`            | How near the cursor must come before anything grabs                                                     |
| `holdBonus`              | How far past the reach a held candidate keeps its grip                                                  |
| `noSnapPull`             | The floor a candidate must beat, so how easily the point comes free                                     |

- [ ] **Step 2: Tune reach first, then the floor, then the weights, then the pointer weight**

They are not independent, and this is the order that converges. Reach sets the scale. The
floor sets the release against that scale. The weights only decide ties, which cannot be
judged until the first two feel right. The pointer weight is last, because it discounts a
pull that the first three have to be producing correctly before the discount means anything.

Tune the pointer weight on a two-contour drag, not a single point: it has no effect on a
one-point selection, where the only point is the one under the hand.

**If reach and precedence need to move apart, add a per-kind reach.** One reach and one
weight per kind cannot state "a metric grabs from further away but a guide wins a tie".
Inkscape gives each family its own tolerance for exactly that. Raising a weight to buy reach
also changes who wins ties, which is the wrong knob.
