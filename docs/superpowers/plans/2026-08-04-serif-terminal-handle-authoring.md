# Serif Terminal Handle Authoring Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make a generated handle on a serif-trimmed terminal segment move one-for-one with the pointer and leave its neighbours alone, by carrying the constructed handle axis through the trim and applying the designer's handle adjustments after the splice instead of before it.

**Architecture:** A serif cuts the last outline segment and splices its terminal onto the cut, so what the designer sees is a sub-arc of the curve the generator solved. Three changes: (1) the de Casteljau split preserves each rebuilt handle's `_axis`, and the anchoring stamps the axis it just aimed at, so the smooth joint next to a serif stops inferring direction from handle length; (2) `generateOutlineFromSkeletonContour` withholds the handle adjustments of a serif-trimmed segment from `offsetCubicSide` and re-applies them to the emitted handles after the caps are spliced, bounded by the emitted segment's own handle domain; (3) the emitted axis is published on provenance so the editor projects the drag onto the axis the generator will actually use. The chord-measure commit `ecc86efa5` is reverted first — it moves the drawn serif by up to 74 units and its purpose is subsumed by (2).

**Tech Stack:** JavaScript ESM, `bezier-js`, mocha + chai (`src-js/fontra-core`, `npm test`), prettier.

**Spec:** `docs/superpowers/specs/2026-08-04-serif-terminal-handle-authoring-design.md`

### Shared test fixture

Tasks 1–6 all use the same skeleton: a three-point stem with a curved approach and a serif on the open start. Define it **once**, at the top of the new describe block in Task 1, and import nothing — the tests are in one file.

```js
const SERIF_HALF = {
  wingLength: 120,
  tipThickness: 30,
  wingSlope: 0,
  tipCutAngle: 0,
  reach: 60,
  tension: 0.7,
  concavity: 0.8,
};

// A stem whose terminal segment curves, so the trim has real curve to eat.
// `capStyle` switches the serif off for the control rows; `offsets` writes a
// handle adjustment as `{ [pointId]: { leftIn|leftOut|rightIn|rightOut: {x, y} } }`.
function serifStem({ capStyle = "serif", offsets = {}, width = 100 } = {}) {
  const point = (id, extra) => ({ id, ...extra, handleOffsets: offsets[id] ?? {} });
  return {
    version: 1,
    nextId: 9,
    contours: [
      {
        id: 1,
        closed: false,
        defaultWidth: width,
        capStyle,
        points: [
          point(2, {
            x: 0,
            y: 0,
            editable: { left: true, right: true },
            serif: {
              left: SERIF_HALF,
              right: SERIF_HALF,
              axisMode: "perpendicular",
              axisAngle: 0,
              undersideCup: 0,
            },
          }),
          { id: 3, x: 120, y: 200, type: "cubic" },
          { id: 4, x: 180, y: 340, type: "cubic" },
          point(5, {
            x: 160,
            y: 400,
            smooth: true,
            editable: { left: true, right: true },
          }),
          { id: 6, x: 260, y: 460, type: "cubic" },
          { id: 7, x: 320, y: 600, type: "cubic" },
          { id: 8, x: 320, y: 800 },
        ],
      },
    ],
    generated: [],
  };
}

// The emitted point carrying one skeleton point's handle, by side and role.
function emitted(result, pointId, side, role) {
  for (const entry of result.provenance) {
    const index = entry.pointMap.findIndex(
      (p) => p?.skeletonPointId === pointId && p.side === side && p.role === role
    );
    if (index >= 0) return result.contours[entry.generatedContourIndex].points[index];
  }
  return null;
}

function moved(before, after) {
  return Math.hypot(after.x - before.x, after.y - before.y);
}
```

**serif-side** handle of the trimmed segment, `emitted(r, 5, "left", "in")` is the **far**
handle of the same segment, and `emitted(r, 5, "left", "out")` is the handle on the **next**

### Task 2: Carry the constructed handle axis through the trim

**Files:**

- Modify: `src-js/fontra-core/src/skeleton-generator.js` — `buildSplitOffCurve`, the four-point branch of `splitTerminalSideForRoundCap`, `anchorTerminalSplit`
- Modify: `src-js/fontra-core/tests/test-skeleton-generator.js`

**Interfaces:**

- Consumes: `serifStem`, `emitted`, `moved` from Task 1.
- Produces: `buildSplitOffCurve(point, sourceHandle)` — second parameter optional; when the source handle carries `_axis`, the rebuilt off-curve carries a copy of it. `anchorTerminalSplit` stamps `_axis` on the handle it re-aims, equal to its `intoStroke` argument.

**Background:** every generated handle is stamped at emission with `_axis`, the exact unit
direction it was constructed on, precisely so `enforceSmoothColinearity` never has to infer
a direction from a rounded position — `sharedLockedAxis` reads it. `buildSplitOffCurve`
rebuilds each off-curve as a bare `{x, y, type}`, so the axis dies at the trim and the
smooth joint next to a serif falls back to the length-weighted estimate. Then any change in
handle length rotates the joint. Measured at **14.7 units** on the fixture; a plain cap
moves the same handle by **0.0**.

A de Casteljau split never changes the direction of the two outer control legs: the left
half's first handle lies on `P0→P1`, and the right half's last handle lies on `P3→P2`. Those
two inherit their source's axis unchanged. The two handles adjacent to the cut genuinely
change direction, so they inherit nothing — and the one that survives emission is re-aimed
by `anchorTerminalSplit` moments later, which is where its axis comes from.

  const offCurve = {
    x: point.x,
    y: point.y,
    type: "cubic",

  // the axis depend on handle length, and rib width sets handle length.

}

### Task 3: Author the handle adjustments after the splice

**Files:**

- Modify: `src-js/fontra-core/src/skeleton-generator.js` — imports, `generateOutlineFromSkeletonContour`, `generateOffsetPointsForSegment`, plus one new function `applySerifAuthoredHandles`
- Modify: `src-js/fontra-core/tests/test-skeleton-generator.js`

**Interfaces:**

- Consumes: `buildSplitOffCurve` / `anchorTerminalSplit` axis stamping from Task 2; `serifStem`, `emitted`, `moved` from Task 1.
- Produces:
  - `collectSerifAuthoredHandles(segments, isClosed, startCapStyle, endCapStyle) -> Set<string>` where each member is `` `${skeletonPointId}/${side}/${role}` `` with `side ∈ {left, right}` and `role ∈ {in, out}`.
  - `applySerifAuthoredHandles(sidePoints, side, authoredKeys) -> Array` — returns a new side array with the authored lengths applied. Pure; does not mutate its input.
  - `generateOffsetPointsForSegment(..., authoredKeys)` — one new trailing parameter, defaulting to `null`.

**Background:** a stored handle adjustment is consumed inside `offsetCubicSide`, i.e.
against the segment the generator solves. The serif then cuts that segment. A sub-arc
responds to its parent's control points at a fraction of the rate and both of its control
points depend on both of the parent's, so the drag is fractional and leaks into its
neighbour. The fix is to withhold those adjustments from the solve and apply them to the
handles that survive the splice.

Both handles of the terminal segment are withheld, not only the serif-side one: the far
handle also shapes the construction curve, and the cut parameter is taken from that curve's
arc length, so leaving it authored pre-trim would move the cut and reintroduce the leak
from the other direction.

Add beside `collectSerifAuthoredHandles`:

```js
// Apply the withheld handle adjustments to the handles that survived the trim.
//
// The designer is looking at a piece of the curve the generator solved, so an
// adjustment consumed before the cut arrives on their handle at a fraction of
// its size and drags the other handle with it. Applied here it is one-for-one
// and local. Direction comes from the stamped axis, never from the emitted
// position: the emitted position is rounded, and recovering a direction from a
// rounded position makes it depend on handle length.
function applySerifAuthoredHandles(sidePoints, side, authoredKeys) {
  if (!authoredKeys?.size) {
    return sidePoints;
  }
  const points = [...sidePoints];
  const isOffCurve = (point) => !!point?.type;
  const authoredIndices = [];
  for (let index = 0; index < points.length; index++) {
    const point = points[index];
    const provenance = point?._provenance;
    if (!isOffCurve(point) || !provenance?.side || !provenance.role) continue;
    if (
      !authoredKeys.has(
        `${provenance.skeletonPointId}/${provenance.side}/${provenance.role}`
      )
    ) {
      continue;
    }
    if (provenance.side !== side) continue;
    authoredIndices.push(index);
  }
  if (!authoredIndices.length) {
    return points;
  }

  // The emitted segment this handle now belongs to: the nearest on-curve either
  // way. Its own box is what bounds the authored lengths, because the segment
  // the solver bounded no longer exists.
  const nearestOnCurve = (from, step) => {
    for (let index = from; index >= 0 && index < points.length; index += step) {
      if (!isOffCurve(points[index])) return index;
    }
    return -1;
  };

  for (const index of authoredIndices) {
    const point = points[index];
    const axis = point._axis;
    if (!axis) continue;
    const anchorIndex =
      nearestOnCurve(index - 1, -1) >= 0 && !isOffCurve(points[index - 1])
        ? index - 1
        : index + 1 < points.length && !isOffCurve(points[index + 1])
          ? index + 1
          : -1;
    if (anchorIndex < 0) continue;
    const farIndex =
      anchorIndex < index
        ? nearestOnCurve(index + 1, 1)
        : nearestOnCurve(index - 1, -1);
    if (farIndex < 0) continue;
    const anchor = points[anchorIndex];
    const far = points[farIndex];
    const farHandleIndex = anchorIndex < index ? farIndex - 1 : farIndex + 1;
    const farAxis = points[farHandleIndex]?._axis ?? {
      x: (anchor.x - far.x) / (Math.hypot(anchor.x - far.x, anchor.y - far.y) || 1),
      y: (anchor.y - far.y) / (Math.hypot(anchor.x - far.x, anchor.y - far.y) || 1),
    };
    const adjustment = point._authoredAdjustment;
    if (!adjustment) continue;

    const domain = buildHandleDomain(anchor, far, axis, farAxis);
    const baseLength = adjustment.detached
      ? 0
      : (point.x - anchor.x) * axis.x + (point.y - anchor.y) * axis.y;
    const placed = {
      x: Math.round(anchor.x + axis.x * baseLength + (adjustment.x || 0)),
      y: Math.round(anchor.y + axis.y * baseLength + (adjustment.y || 0)),
    };
    const requested = (placed.x - anchor.x) * axis.x + (placed.y - anchor.y) * axis.y;
    const tension = requested / domain.startReach;
    const clamped =
      Math.min(Math.max(tension, domain.minStartTension), domain.maxStartTension) *
      domain.startReach;
    points[index] = {
      ...point,
      x: Math.round(anchor.x + axis.x * clamped),
      y: Math.round(anchor.y + axis.y * clamped),
    };
  }
  return points;
}
```

- [ ] **Step 1: Feature model §8 — add the authored-layer rule**

Under "The release — the one rule to keep", add a sibling subsection:

```markdown
### What a designer's handle adjustment means here

**On a trimmed terminal the authored handle layer applies after the cut, not
before it.** A serif eats the end of the segment the generator solved, so the
handles a designer sees belong to a piece of that curve — and a piece responds
to its parent's control points at a fraction of the rate, with both of its
control points depending on both of the parent's. Consumed before the cut, an
adjustment therefore arrived fractional and dragged its neighbour with it.

The terminal segment's two adjustments are withheld from `offsetCubicSide` and
applied to the surviving handles after the splice, along the axis the trim and
`anchorTerminalSplit` stamped, bounded by the emitted segment's own handle
domain. **Both** handles, not only the serif-side one: the far handle shapes the
curve whose arc length the cut is measured along, so leaving it authored before
the cut moves the cut.

The order on a trimmed terminal is therefore: natural answer → pinned tension →
trim → attached adjustments → detached handles. The pin still governs the whole
construction segment and the authored lengths govern the emitted one. They
describe different curves and compose without a precedence rule, the same way
the pin and the split already do.

The axis an authored handle is measured along travels forward on its
provenance as `authoredAxis`, because for the serif-anchored handle it is the
terminal's depth axis rather than the skeleton's handle direction, and the
editor has to project a drag onto the same axis the generator will use.
```
