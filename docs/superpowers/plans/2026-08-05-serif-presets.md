# Serif Presets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give a master a named list of serif terminal shapes. A designer captures a drawn foot into a preset, edits it, and applies it to any other serifed terminal in one armed press.

**Architecture:** Three layers, in order. (1) The serif model drops `null` as a stored value, so every wing field always holds a number and the unreachable contour-level fallback comes out. (2) A new source-default list `customSerifs` holds `{ name, linked, undersideCup, left{9}, right{9} }` per master, next to the existing width and cap profile lists, plus three new numbers that seed a new serif. (3) The defaults panel edits the list and the parameters panel applies, captures and updates it. Everything writes through the one serif writer the panel already owns.

**Tech Stack:** JavaScript ESM, mocha + chai (`src-js/fontra-core`, `npm test`), prettier.

**Spec:** `docs/superpowers/specs/2026-08-05-serif-presets-design.md`

### Shared test fixture

Tasks 1, 3 and 5 use one skeleton: a two-point stem with a serif on the open
start. Define it once at the top of the new describe block in Task 1.

```js
// A stem with a serif on the open end. `serif` goes onto the first point
// verbatim, so a test can store nulls, store numbers, or store nothing.
function serifStem({ serif = undefined, contourSerif = undefined } = {}) {
  return {
    version: 1,
    nextId: 5,
    contours: [
      {
        id: 1,
        closed: false,
        defaultWidth: 100,
        capStyle: "serif",
        ...(contourSerif ? { serif: contourSerif } : {}),
        points: [
          { id: 2, x: 0, y: 0, ...(serif ? { serif } : {}) },
          { id: 3, x: 0, y: 400 },
        ],
      },
    ],
    generated: [],
  };
}

const ALL_NULL_HALF = Object.fromEntries(SERIF_HALF_FIELDS.map((f) => [f, null]));
```

## Task 1 — The serif model drops `null`

**This is the only task that can move a drawn shape, and it must not.** Everything
else is additive.

### What is true today, verified in the tree

- `normalizeSerifHalf` writes `null` for any non-finite field.
- `resolveSerifHalf` in the generator reads `pointSerif → contourSerif → SERIF_HALF_DEFAULTS`.
- `SERIF_HALF_DEFAULTS` is **not all zeros**: `tension` 0.7, `concavity` 0.8, `easeCurvature` 0.5, the other six 0.
- The contour level has **no writer anywhere in the tree**. It is read in three places and set in none.

So a `null` today resolves to the default table, not to zero. A migration to zero
would flatten the bracket of every untouched serif.

### Steps

- [ ] Write the characterization test first: build `serifStem({ serif: { left: ALL_NULL_HALF, right: ALL_NULL_HALF } })`, generate it, and snapshot the emitted terminal points. This is the shape that must not move.
- [ ] Add `SERIF_HALF_MIGRATION` in `skeleton-model.js` holding the same nine values `SERIF_HALF_DEFAULTS` holds today. Import it, or re-export the existing constant — one copy of the numbers, never two.
- [ ] Change `normalizeSerifHalf` to fill a non-finite field from that table instead of writing `null`.
- [ ] Change `normalizeSerif` to fill `undersideCup` with 0 instead of `null`. `axisAngle` already fills with 0 and does not change.
- [ ] Delete the `contourSerif` fallback from `resolveSerifHalf`, from the `axisMode` / `axisAngle` / `undersideCup` reads in `buildSerifCap`, and from the two `contourSerif` arguments the generator passes in. Remove the parameter, do not pass null into it.
- [ ] Delete the `entry.contour.serif` fallback from `summarizeSkeletonSerifSelection`.
- [ ] Delete the `contour.serif` fallback from the serif read helper in `skeleton-panel-edits.js` (around line 738).
- [ ] Run the characterization test. The emitted points must be identical.
- [ ] Add: a contour-level serif block on the fixture no longer reaches the outline.
- [ ] Add: normalization never returns `null` for any of the nine fields or for `undersideCup`.
- [ ] Regenerate the golden fixtures. **The diff must be empty.** If it is not, stop and find what moved.

### Acceptance

Full suite green. Fixture diff empty. `grep -rn "contour.serif\|contourSerif" src-js/` returns only the generator's contour copy at line 210, which can also go if nothing else reads it.

## What this plan does not do

- Wing-only preset storage. The scope select applies half a preset. It does not store half of one.
- Reordering the list.
- Presets shared between masters.
- The contour cap style, which has no writer either. Cap work, not serif work.
